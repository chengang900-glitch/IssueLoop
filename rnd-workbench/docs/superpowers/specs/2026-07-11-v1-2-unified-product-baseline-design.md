# 研发工作台 V1.2 统一产品基线设计

**状态：** 待评审  
**日期：** 2026-07-11  
**适用范围：** `rnd-workbench` 的后续功能修复、页面调整、接口调整和验收测试  
**基线：** PRD V1.0、PRD V1.1、API V1.0、API V1.1 与当前已部署实现

## 1. 目标与边界

V1.2 不引入新的专业测试平台、工时、自动化规则或企业微信 SSO。目标是把已经出现的功能统一为一套可解释、可验证的产品规则，优先消除导航混乱、权限不一致、页面展示异常和接口契约漂移。

V1.2 的成功标准：

- 用户能从任一导航入口明确知道当前数据范围和可执行操作。
- 同一操作在产品说明、前端显示、接口权限和服务端校验中具有一致结果。
- 管理员、项目管理员、成员、访客在所有项目场景下均有明确边界。
- 新建项目、项目较多、空数据、无权限、归档项目和接口失败均有确定页面行为。

## 2. 信息架构与页面规则

### 2.1 主导航

| 页面 | 数据范围 | 主要目的 | 可见用户 |
|---|---|---|---|
| 工作台 | 当前项目 | 查看个人待办、项目动态、到期提醒和项目概览 | 项目成员、项目管理员、访客 |
| 待我解决 | 当前项目，`ownerId=当前用户` 且状态非“已完成/已关闭” | 处理本人仍需完成的事项 | 项目成员、项目管理员、访客 |
| 指派给我 | 当前项目，`ownerId=当前用户` 且状态非“已关闭” | 查看本人历史及当前受理事项 | 项目成员、项目管理员、访客 |
| 全部工作项 | 当前项目全部可访问工作项 | 查询、筛选、创建、批量处理 | 项目成员、项目管理员、访客 |
| 流程看板 | 当前项目全部可访问工作项 | 按状态查看流程进展；V1.2 不支持拖拽改状态 | 项目成员、项目管理员、访客 |
| 项目简报 | 当前项目汇总指标和风险项 | 查看项目概况，不替代报表中心 | 项目成员、项目管理员、访客 |
| 项目管理 | 按当前用户权限可访问的项目 | 搜索、筛选、进入项目、维护项目信息和项目团队 | 全部已登录用户 |
| 用户管理 | 全部用户 | 创建、启停、重置密码、维护用户资料 | 系统管理员 |

“待我解决”与“指派给我”的差异必须保留：前者排除已完成，后者保留已完成但排除已关闭；页面标题和筛选条件要同步显示。

### 2.2 项目切换和项目较多场景

- 左侧不显示项目快捷列表、项目数量或“查看全部项目”链接；仅保留主菜单“项目管理”。
- 顶部当前项目下拉仅承担项目上下文切换，默认展示最近访问的未归档项目；不承担项目维护入口。
- “项目管理”使用筛选列表，不使用项目卡片。固定提供关键字搜索、状态（进行中/已归档）、“我负责”和“我参与”筛选。
- 项目列表字段为项目名称、状态、项目管理员、成员数、最近更新时间；每行提供“进入项目”。
- 系统管理员在“项目管理”看到全部项目及“新增项目、编辑、设置团队、归档/恢复”操作；项目管理员只看到本人参与项目，并可“编辑、设置团队”；成员和访客只看到本人参与项目和“进入项目”。
- 归档项目只在状态筛选为“已归档/全部”时出现。当前项目被归档后，当前会话跳回“项目管理”，显示“该项目已归档”的说明；已打开页面不再允许写入。

### 2.3 页面状态

每个数据页面必须至少定义以下状态：

| 状态 | 页面行为 |
|---|---|
| 加载中 | 显示骨架或加载提示，禁止重复提交 |
| 空数据 | 说明数据为空的原因；仅有写权限的用户显示创建入口 |
| 无项目 | 管理员显示“创建第一个项目”；其他用户显示“请联系项目管理员加入项目” |
| 无权限 | 显示无权限提示并保留可返回入口，不保留可执行按钮 |
| 接口失败 | 显示可理解的错误提示和“重试”操作；不把 500 解释为用户输入错误 |

## 3. 权限与账户规则

### 3.1 两级权限模型

系统角色仅有 `ADMIN` 和 `USER`；项目角色仅有 `PROJECT_ADMIN`、`MEMBER`、`GUEST`。岗位（项目经理、实施顾问、开发顾问、测试顾问）和部门是组织资料，不直接授予系统或项目权限。

| 操作 | ADMIN | PROJECT_ADMIN | MEMBER | GUEST |
|---|---|---|---|---|
| 创建项目 | 允许 | 不适用 | 不允许 | 不允许 |
| 查看本人项目内容 | 加入项目后允许 | 允许 | 允许 | 允许 |
| 查看全部项目管理清单 | 允许 | 不允许 | 不允许 | 不允许 |
| 编辑项目基本信息 | 允许 | 仅限本人为项目管理员的项目 | 不允许 | 不允许 |
| 归档/恢复项目 | 允许 | 不允许 | 不允许 | 不允许 |
| 管理项目成员 | 允许 | 仅限本人为项目管理员的项目 | 不允许 | 不允许 |
| 管理模块、迭代 | 加入项目后按项目角色执行 | 允许 | 不允许 | 不允许 |
| 创建、编辑、流转工作项 | 加入项目后按项目角色执行 | 允许 | 允许 | 不允许 |
| 删除工作项、批量删除 | 加入项目后按项目角色执行 | 允许 | 不允许 | 不允许 |
| 查询、筛选、关注、导出 | 加入项目后允许 | 允许 | 允许 | 允许 |
| 管理系统用户 | 允许 | 不允许 | 不允许 | 不允许 |

系统管理员不是任意项目内容的默认成员。这样保留项目隔离；系统管理员可在“项目管理”中维护任何项目的成员（包括指定首位项目管理员），但需要处理具体项目内容时，仍必须把自己加入项目并取得相应项目角色。项目管理员只能维护自己担任项目管理员的项目团队。项目管理页读取成员摘要不代表拥有项目内容的读写权限。

### 3.2 用户生命周期

- 用户名为邮箱，创建后不可修改；姓名可修改。
- 系统管理员创建用户时，初始密码固定为 `123456`，系统标记“首次登录必须修改密码”。
- 被禁用用户不能登录；已登录会话在下一次受保护接口请求时被拒绝。
- 用户可修改自己的部门和密码；岗位由系统管理员维护，用户不可自行修改。
- 重置密码后再次设置“首次登录必须修改密码”。
- 最后一个系统管理员不得被禁用或降级；项目中最后一个项目管理员不得被移除或降级。

## 4. 项目与工作项生命周期

### 4.1 项目

项目状态仅有“进行中”和“已归档”。创建即为进行中，创建人自动成为项目管理员。归档不删除项目、工作项、附件或活动记录；恢复后保留全部历史数据。

归档前必须确认：归档会禁止工作项创建、编辑、状态流转、评论、上传和成员调整；允许已有成员只读查看历史和导出。系统管理员可恢复项目。

### 4.2 工作项类型与编号

工作项类型为需求、任务、测试、缺陷，对应前缀 `REQ`、`TASK`、`CASE`、`BUG`。编号采用“类型前缀 + 全局原子递增序号”，例如 `BUG-1001`；编号全局唯一，不随项目重复。

优先级仅有 `P0`、`P1`、`P2`、`P3`，默认 `P2`；严重程度仅有“致命、严重、普通、轻微”，默认“普通”。模块和迭代均可为空；负责人可为空，表示尚未分配。

所有类型使用同一状态机，但必须满足以下业务约束：

- 创建时状态为“新提交”，负责人可为空。
- “分配给我”仅在负责人为空且状态允许转入“已分配”时可用。
- “已完成”和“已关闭”是终态；重新打开统一回到“新提交”。
- 关闭操作必须填写关闭原因；重新打开必须填写原因并记录活动。
- 缺陷在“待测试/测试中”状态应填写复现步骤、期望结果和实际结果；非缺陷字段可为空。
- 验收动作由项目成员或项目管理员完成；V1.2 不按岗位限制验收权限。

### 4.3 状态机

允许转换保持既有规则：

`新提交 → 待评估 → 已分配 → 处理中 → 待测试 → 测试中 → 待验收 → 已完成 → 已关闭`

任何非终态可关闭；已完成和已关闭可重新打开到新提交。每次流转必须记录操作者、原状态、新状态、时间和原因（关闭/重新打开时必填）。状态变更产生站内通知：负责人、关注者和被 @ 提及用户可收到与其有关的通知，操作者本人不重复接收。

### 4.4 附件、描述图片与评论

- 项目成员和项目管理员可上传；访客只读下载。
- 描述框可粘贴多张图片，创建或编辑后按原文位置预览；图片也是工作项附件，遵循同一权限。
- 单文件上限 50MB；图片数量和总大小由前端在上传前提示，服务端仍做最终校验。
- 上传者可删除自己上传的附件，项目管理员可删除任意附件；删除后描述中的图片位置显示“图片已删除”，不得显示破损图片。
- 评论支持 @ 提及项目成员；提及非项目成员必须被拒绝。

## 5. 首页、筛选、批量与导出

### 5.1 指标口径

| 指标 | 计算规则 |
|---|---|
| 我的待办 | 当前用户负责，状态不为已完成/已关闭 |
| 待接收 | 当前项目中负责人为空且状态为新提交或待评估 |
| 处理中 | 当前项目状态为处理中 |
| 待验收 | 当前项目状态为待验收 |
| 今日到期 | 截止日处于当天且状态非终态 |
| 已逾期 | 截止日早于当天且状态非终态 |

工作台展示的所有数字必须来自同一项目范围和上述口径；没有数据时显示 0，不允许使用演示数据或固定数值。

### 5.2 筛选与视图

- 预设个人视图：我创建的、指派给我、待我解决、我关注的、未关闭问题。
- 保存筛选器为“用户 + 项目”私有数据，支持创建、重命名、复制、删除和设为默认。
- 保存筛选器统一使用键值条件：`type`、`status`、`ownerId`、`creatorId`、`sprintId`、`priority`、`severity`、`module`、`tag`、`dueFrom`、`dueTo`、`keyword`、`view`。V1.2 不采用“字段/运算符/值数组”契约。
- 列设置、排序、分组同样为“用户 + 项目”私有数据。后端负责筛选和排序，前端负责当前页展示分组。

### 5.3 批量与导出

- 批量更新仅成员和项目管理员可用；批量删除仅项目管理员可用；单次最多 200 条。
- 批量状态变更必须逐条校验状态机，部分失败不回滚已成功项，并返回逐项失败原因。
- 批量标签为“新增/移除”，不覆盖未涉及标签。
- 导出仅包含当前用户有权访问的项目数据，遵循当前筛选、排序和展示列；文件包含导出人、时间和筛选摘要，保留 24 小时。

## 6. 接口契约调整清单

| 范围 | V1.2 决策 |
|---|---|
| 工作项列表 | 保持 `GET /projects/{id}/work-items`；`groupBy` 不进入接口结果，只保存为列表偏好 |
| 保存筛选器 | 使用对象型 `conditions`；新增复制筛选器接口或在创建时接受已有条件 |
| 关注 | 保留关注/取消关注；补充关注者列表和当前用户关注工作项列表，均先校验项目成员关系 |
| 通知 | 支持未读、类型、工作项筛选；单条已读和全部已读必须幂等 |
| 项目归档 | 保留 `PUT /projects/{id}/archive?archived=true|false`，并在所有写接口校验项目未归档 |
| 项目成员 | 管理接口仅项目管理员可用；系统管理员需先成为项目管理员 |
| 用户资料 | 用户更新本人部门和密码；系统管理员更新姓名、部门、岗位、系统角色与状态 |

接口文档必须为每个请求声明字段类型、必填性、枚举、默认值、权限、成功响应、错误码及至少一个失败示例。实现不能新增未记录的请求字段或返回字段。

## 7. P0/P1/P2 实施基线

### P0：先恢复稳定和一致性

1. 修复项目目录卡片 DOM/CSS 结构，保证多项目显示正常。
2. 为归档项目的全部写操作增加一致校验，并处理当前项目被归档后的前端跳转。
3. 移除侧栏项目快捷列表，建立带搜索和常用筛选的项目管理列表，并按本规格限制操作权限。
4. 补齐首页指标真实计算和空/错误状态。
5. 更新 API 文档，使保存筛选器、关注、分组和项目权限与实现一致。

### P1：补齐产品闭环

1. 补充项目管理员保底规则、用户管理员保底规则、关闭/重新打开原因。
2. 补充筛选器复制、关注者列表、我关注的工作项列表。
3. 补充附件删除后的图片占位、@ 提及成员校验、归档项目只读提示。
4. 为项目创建、项目切换、访客、成员、项目管理员、系统管理员补接口和页面验收测试。

### P2：体验与治理

1. 统一页面加载、空数据、无权限、网络错误状态。
2. 为项目简报补充风险项、到期项和活动详情入口。
3. 增加审计日志的查询入口、备份恢复说明与生产巡检清单。

## 8. 验收场景

| 编号 | 场景 | 通过条件 |
|---|---|---|
| A01 | 新建项目 | 管理员创建后自动成为项目管理员，进入空工作台，不出现服务器错误 |
| A02 | 多项目管理 | 侧栏不显示项目快捷列表；项目管理列表支持搜索和状态/我负责/我参与筛选，项目操作与用户角色匹配 |
| A03 | 访客访问 | 能查询、筛选、关注、导出；所有写入、批量修改和删除被拒绝 |
| A04 | 归档项目 | 成员可只读查看和导出，所有写操作被拒绝；恢复后重新可写 |
| A05 | 状态流转 | 非法转换被拒绝；关闭和重新打开均记录原因和活动 |
| A06 | 用户管理 | 新用户首次登录必须改密码；禁用用户不能登录；最后一个系统管理员不能被禁用 |
| A07 | 保存筛选器 | 私有、跨登录保留、可复制；未知条件字段被拒绝 |
| A08 | 首页指标 | 指标与列表结果口径一致，空项目全部为 0，不显示模拟数值 |
| A09 | 描述图片 | 可粘贴多图并预览；附件删除后显示明确占位，不显示破损图片 |
| A10 | 接口失败 | 页面显示可理解错误和重试入口，用户输入错误与服务器异常不混淆 |

## 9. 非目标

V1.2 不包含企业微信 SSO、工时、燃尽图、拖拽看板、共享筛选器、可配置角色、Webhook 可视化配置、Excel 导入、对象存储迁移、微服务化或前端框架迁移。
