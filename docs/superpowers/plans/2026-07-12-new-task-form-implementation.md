# 新建任务表单优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将新建任务改为“核心信息—富文本描述—附件—任务属性”的单页表单，并完整保存关注人、预计工时、模块层级和关联任务。

**Architecture:** 在现有 Spring Boot 工作项创建接口上扩展结构化字段；关注人复用既有 `work_item_watchers` 表，预计工时和模块层级写入工作项，关联任务使用一张无方向的关系表。前端继续使用原生 JavaScript，以受限 `contenteditable` 编辑器替换 textarea；图片先上传为附件，再用现有 `[[image:<id>]]` 标记回填到正文位置。

**Tech Stack:** Spring Boot 2、Spring Data JPA、Flyway、H2/PostgreSQL、Vanilla JavaScript、CSS、JUnit 5、Mockito。

## Global Constraints

- 任务类型仅允许：需求、任务、测试、缺陷。
- 标题、所属项目、任务类型和描述必填；其他任务属性放在描述和附件之后。
- 不新增发布里程碑或受影响里程碑。
- 关注人和关联任务仅限当前项目成员可访问的任务；关联不得指向自身或重复。
- 预计工时单位为小时，使用非负、0.5 小时粒度的小数。
- 描述富文本只允许受控标签和图片标记，禁止脚本、事件属性和任意 URL。
- 状态固定为新建、进行中、延期处理、已完成、已验收、验收不通过、已拒绝；重新开始是回到进行中的操作记录。
- 延期驳回回到进行中并保留原截止日期，不进入已拒绝。
- 工作区未初始化 Git；实施时不执行提交操作。

- [ ] **Step 3: 添加 H2 与 PostgreSQL 的同构迁移**

两个 V8 文件分别使用方言对应的自增主键，并包含以下结构：

```sql
ALTER TABLE modules ADD COLUMN parent_id BIGINT;
ALTER TABLE work_items ADD COLUMN module_id BIGINT;
ALTER TABLE work_items ADD COLUMN submodule_id BIGINT;
ALTER TABLE work_items ADD COLUMN estimated_hours DECIMAL(8,1);

CREATE TABLE work_item_relations (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    source_work_item_id VARCHAR(16) NOT NULL REFERENCES work_items(id) ON DELETE CASCADE,
    target_work_item_id VARCHAR(16) NOT NULL REFERENCES work_items(id) ON DELETE CASCADE,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uq_work_item_relation UNIQUE (source_work_item_id, target_work_item_id)
);
CREATE INDEX idx_work_item_relations_source ON work_item_relations(source_work_item_id);
CREATE INDEX idx_work_item_relations_target ON work_item_relations(target_work_item_id);
```

PostgreSQL 将 H2 的主键定义替换为 `BIGSERIAL PRIMARY KEY`；关系 ID 由服务层按字典序规范化，始终令 `source_work_item_id < target_work_item_id`。

请求与响应使用以下字段名，创建和编辑保持一致：


在 `WorkItemService.create` 中执行顺序固定为：校验描述非空 → 校验工时非负且 `scale() <= 1` → 校验负责人、关注人属于项目 → 校验主/子模块归属及父子关系 → 校验迭代归属 → 保存工作项 → 去重保存关注人 → 规范化并保存关联任务 → 写创建活动 → 通知除创建人外的关注人。

关联规范化方法必须为：

```java
private String[] relationPair(String left, String right) {
    if (left.equals(right)) throw new BusinessException(ErrorCode.BAD_REQUEST, "任务不能关联自身");
    return left.compareTo(right) < 0 ? new String[] { left, right } : new String[] { right, left };
}
```

`toDto` 使用关系仓储双向查询，返回关联任务的 `id`、`title`、`type`、`status`；关注人返回既有 `watchers(id)` 的成员摘要。创建时通过 `notificationService.notifyWatchers(id, creatorId, "TASK_CREATED", "创建了任务：" + item.getTitle())` 发送通知。
