# 项目档案与项目编号设置 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为实施与开发项目提供完整项目档案、可维护里程碑和管理员配置的项目编号规则。

**Architecture:** 后端用 Flyway V11 扩展项目表并新增里程碑、设置和编号计数表；`ProjectService` 集中管理编号生成、档案校验和里程碑权限。前端在项目管理页显示摘要，使用项目档案页面维护详情和里程碑，管理员专属系统设置页维护编号前缀。

**Tech Stack:** Spring Boot 2.7、Spring Data JPA、Flyway、H2/PostgreSQL、Vanilla JavaScript、CSS、JUnit 5、Mockito。

## Global Constraints

- 不新增合同、预算、回款或采购字段。
- 编号仅由服务端生成，格式固定为 `{prefix}-{YYYYMM}-{threeDigitSequence}`；既有编号不可编辑。
- 前缀仅允许 1-16 位大写字母、数字或连字符，默认 `PRJ`。
- 修改前缀只影响后续新建项目；历史项目使用 `LEGACY-{id}` 回填。
- 系统设置只允许系统管理员；项目档案和里程碑编辑只允许系统管理员或项目管理员。
- 工作区未初始化 Git；不执行提交。

- [ ] **Step 3: 添加 H2 / PostgreSQL 对应的 V11 迁移**

为 `projects` 增加 `code`、`project_type`、`business_line`、`customer_name`、`delivery_location`、三类负责人 ID、日期、阶段、状态、健康度、交付文本、实施方式和运维日期。创建：

```sql
CREATE TABLE project_code_counters (
  prefix VARCHAR(16) NOT NULL,
  period VARCHAR(6) NOT NULL,
  last_sequence INTEGER NOT NULL,
  PRIMARY KEY (prefix, period)
);
CREATE TABLE system_settings (
  setting_key VARCHAR(64) PRIMARY KEY,
  setting_value VARCHAR(255) NOT NULL,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
CREATE TABLE project_milestones (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  project_id BIGINT NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  name VARCHAR(128) NOT NULL,
  planned_date DATE NOT NULL,
  completed_date DATE,
  status VARCHAR(16) NOT NULL DEFAULT '未开始',
  description VARCHAR,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

PostgreSQL 的里程碑主键使用 `BIGSERIAL`。插入 `project_code_prefix=PRJ`，并把历史项目更新为 `LEGACY-{id}`、实施/立项/进行中/正常/混合的兼容默认值。

- [ ] **Step 4: 实现实体与仓储**

里程碑仓储提供 `List<ProjectMilestone> findByProjectIdOrderByPlannedDateAsc(Long projectId)`；设置仓储使用 `findById`。
