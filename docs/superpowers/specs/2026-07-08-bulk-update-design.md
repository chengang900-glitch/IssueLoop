# 工作项批量处理设计

日期：2026-07-08  
状态：已确认，待实施

## 1. 目标

支持项目成员对最多 200 个工作项批量修改状态、负责人、优先级、Sprint、模块和标签。每个工作项独立处理，允许部分成功并返回可操作的失败原因。

## 2. API

`POST /api/v1/projects/{projectId}/work-items/bulk-update`

请求体：

- `ids`：工作项 ID 数组，1–200 个，不允许重复。
- `status`：可选，目标状态。
- `ownerId`：可选，目标负责人。
- `sprintId`：可选，目标 Sprint。
- `priority`：可选，`P0|P1|P2|P3`。
- `module`：可选，目标模块名。
- `addTags`：可选，要新增的标签数组。
- `removeTags`：可选，要移除的标签数组。

请求至少包含一个修改字段。标签去重，新增标签保留原有其他标签，移除不存在的标签不报错。当同一标签同时出现在新增和移除列表时，请求整体返回 400。

## 3. 响应

返回：

- `successes`：成功更新的工作项 ID 数组。
- `failures`：失败项数组，每项包含 `id`、`code` 和 `reason`。

请求级校验失败直接返回 400 或 403，不进入逐项处理。进入逐项处理后，即使全部工作项失败，仍返回结构化的成功/失败结果。

## 4. 逐项校验

- 工作项必须存在且属于路径中的项目。
- 状态变更必须通过现有状态机，不允许跨状态跳转。
- 负责人必须是当前项目成员。
- Sprint 必须存在且属于当前项目。
- 优先级仅允许 `P0|P1|P2|P3`。
- 模块使用现有工作项文本字段，本阶段不强制关联模块主数据。
- 标签去除首尾空白和空值，并按首次出现顺序保存。

## 5. 事务和活动记录

调度服务本身不开启整批事务。每个工作项调用独立事务方法，单项保存或活动记录失败不影响已成功项。

成功项写入一条 `BULK_UPDATE` 活动，内容概括本次实际修改的字段。

## 6. 权限

- 项目成员和项目管理员可调用。
- 访客禁止调用。
- 非项目成员禁止调用。
- 用户身份仅从 JWT 解析。

## 7. 前端交互

- 工作项行复选框支持单选，表头复选框选中当前已渲染结果。
- 有选中项时显示批量操作入口及选中数量。
- 批量操作弹窗可设置本次需要修改的字段；空字段不发送。
- 提交后显示成功数和失败数。存在失败项时，列出工作项 ID 和失败原因。
- 完成后刷新当前列表并清空已成功项；失败项保持选中，便于修正后重试。

## 8. 本次不实现

- 批量删除。后续单独设计项目管理员权限和二次确认。
- 跨项目批量修改。
- 批量修改标题、描述、类型、严重程度或截止时间。
- 标签整体覆盖。

## 9. 验收和测试

- 拒绝空 ID、超过 200 条、重复 ID 和无修改字段的请求。
- 访客和非项目成员无法调用。
- 工作项项目归属和状态机逐项校验。
- 批量中单项失败时，其他合法项仍成功并持久化。
- 负责人和 Sprint 校验项目范围。
- 标签新增、移除、去重和冲突校验正确。
- 前端全选、选中计数、批量弹窗和结果摘要正常。
- JavaScript 语法检查、后端全量测试和 Maven 打包全部通过。
