# 列表显示列与排序偏好设计

日期：2026-07-08  
状态：已确认，待实施

## 1. 目标

将工作项列表的显示列、列顺序和排序方式按“用户 + 项目”持久化，使用户重新登录或切换项目后恢复各自偏好。

## 2. 列配置边界

- 固定列：复选框、ID、标题。固定列不可隐藏或调整顺序。
- 可配置列：类型、状态、负责人、优先级、迭代、模块、严重程度、创建人、到期日、创建时间、更新时间。
- 至少保留一个可配置列。
- 本阶段不实现拖拽、列宽调整和分组。

## 3. 数据与接口

使用已存在的 `user_view_preferences` 表，不新增数据库迁移。

- `GET /api/v1/projects/{projectId}/view-preference`
- `PUT /api/v1/projects/{projectId}/view-preference`

返回和更新内容包括：

- `columns`：可配置列的有序字段名数组。
- `sort`：`<field>,<direction>` 格式的排序字符串。
- `groupBy`：本阶段固定为空，仅保留数据结构。

尚未保存偏好时，GET 返回系统默认配置，不立即写入数据库。PUT 使用 upsert 语义。

## 4. 默认值与白名单

默认显示列顺序：`type, status, owner, priority, sprint, dueDate`。  
默认排序：`createdAt,desc`。

排序字段白名单：`createdAt, updatedAt, dueDate, priority, title`。  
排序方向白名单：`asc, desc`。

后端拒绝未知列、重复列、空列数组、非法排序字段和非法排序方向。

## 5. 权限

- 项目成员和访客均可查询和更新本人偏好。
- 非项目成员返回 403。
- 接口不接收用户 ID，用户身份只从 JWT 中解析。
- 用户不能读取或修改其他用户的偏好。

## 6. 前端交互

- 现有“视图设置”按钮打开配置弹窗。
- 弹窗按当前顺序展示可配置列，每列提供显示勾选、上移和下移操作。
- 排序字段和方向在同一弹窗内配置。
- 保存成功后立即重新查询并渲染表头与数据行。
- 高级筛选弹窗修改排序时，同步更新当前项目的偏好。
- 应用已保存筛选器时，筛选器中的排序仅用于当次查询，不覆盖持久化偏好；用户在视图设置或高级筛选中主动保存后才更新偏好。

## 7. 渲染规则

表头和每行使用同一份列定义映射动态生成，保证顺序一致。固定列始终位于最前。表格 CSS grid 根据实际可见列数动态设置列宽。

## 8. 验收与测试

- 无数据时返回默认配置。
- 首次 PUT 创建偏好，再次 PUT 覆盖同一用户和项目的偏好。
- 不同用户或不同项目的偏好相互隔离。
- 未知列、重复列、空列数组和非法排序被拒绝。
- 项目切换后表头、数据行和排序与当前项目偏好一致。
- JavaScript 语法检查、后端全量测试和 Maven 打包全部通过。
