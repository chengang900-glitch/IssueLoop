# 研发工作台 PRD V1.1 更新设计

日期：2026-07-07  
状态：待生成正式 PRD

## 1. 交付物

新建 `研发工作台-PRD-V1.1.docx`，保留现有 `研发工作台-PRD-V1.0.docx` 不变。V1.1 文档继承 V1.0 已确认的产品目标、角色、核心工作项模型和状态机，并新增成熟问题管理平台所需的效率功能。

## 2. V1.1 范围

### 2.1 个人工作视图

- 我创建的：创建人为当前用户。
- 指派给我的：负责人为当前用户且未关闭。
- 待我解决：负责人为当前用户且状态不属于已完成、已关闭。
- 我跟踪的：当前用户主动关注的工作项。
- 未关闭问题：状态不属于已关闭。

### 2.2 自定义筛选器

- 支持按类型、状态、负责人、创建人、优先级、严重程度、迭代、模块、标签、截止时间组合筛选。
- 用户可保存、重命名、删除个人筛选器。
- 支持将一个筛选器设为当前项目默认视图。
- V1.1 不支持跨用户共享筛选器。

### 2.3 列表配置与检索

- 用户可选择显示列并调整列顺序。
- 支持按更新时间、创建时间、截止时间、优先级排序。
- 支持按状态、负责人、类型、迭代分组，并可取消分组。
- 普通搜索匹配 ID、标题、描述、模块和标签。
- 高级搜索使用结构化条件构建器，不引入自定义查询语言。

### 2.4 批量处理

- 批量修改状态、负责人、优先级、迭代、模块和标签。
- 批量状态修改必须逐项执行状态机校验；部分失败时返回成功项和失败原因。
- 批量删除仅项目管理员可用，并要求二次确认。

### 2.5 关注与通知中心

- 用户可关注或取消关注工作项。
- 工作项被指派、状态变化、评论提及、临近到期时产生站内通知。
- 关注者接收状态变化和新评论通知。
- 通知中心支持未读筛选、单条已读和全部已读。

### 2.6 列表导出

- 导出当前筛选结果为 Excel。
- 导出字段遵循当前显示列与顺序。
- 仅导出用户有权访问的数据。
- V1.1 不做 Excel 批量导入。

## 3. 数据模型增量

- `saved_filter`：用户、项目、名称、条件 JSON、排序、分组、显示列、是否默认。
- `work_item_watcher`：工作项、用户、关注时间，工作项与用户联合唯一。
- 现有通知表继续使用，不新增第二套消息模型。
- 工作项已有字段继续支持类型、状态、负责人、创建人、优先级、严重程度、迭代、模块、标签和截止时间。

## 4. 权限

- 访客可以查询、筛选、保存个人视图、关注和导出，不可批量修改。
- 项目成员和项目管理员可以批量修改工作项。
- 只有项目管理员可以批量删除。
- 筛选器、显示列和默认视图均为用户个人配置。

## 5. V2 路线图

- 项目统计中心和可配置报表。
- 里程碑及里程碑进度。
- 自动化规则：触发条件、判断条件和执行动作。
- 独立测试管理：测试计划、测试集、执行记录和测试报告。
- 系统公告、帮助中心和完整设置中心。
- 企业微信 SSO、消息推送和对象存储。

## 6. 验收重点

1. 用户可通过个人视图快速定位本人相关工作项。
2. 组合筛选可以保存，并在重新登录后恢复。
3. 显示列、排序和分组配置对当前用户持久化。
4. 批量状态修改严格遵守现有状态机并报告逐项结果。
5. 关注工作项后可收到状态和评论通知。
6. Excel 导出结果与当前筛选和显示列一致。
7. 所有查询、批量操作和导出均遵守项目权限。

## 7. 文档处理原则

- 新 PRD 采用 V1.1 完整文档，不只生成差异补丁。
- 已经开发的 V1 核心能力标记为“已有基础能力”。
- 新增的 V1.1 功能标记为“计划开发”。
- API 接口和数据库 DDL 留待 V1.1 PRD 评审后单独设计。
