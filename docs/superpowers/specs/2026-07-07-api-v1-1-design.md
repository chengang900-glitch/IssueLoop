# 研发工作台 API V1.1 设计说明

日期：2026-07-07  
状态：待生成正式 API 文档

## 1. 设计目标

在保持 `/api/v1` 兼容的前提下增加 V1.1 协作效率接口。已有接口不改变路径和响应结构；新增接口继续使用 JWT、统一 `ApiResponse`、现有错误码和项目权限校验。

## 2. 新增资源

- `saved-filters`：用户在项目内保存的筛选、排序、分组和显示列配置。
- `view-preference`：当前用户在项目内未绑定具体筛选器的列表偏好。
- `watchers`：工作项关注关系。
- `bulk-actions`：工作项批量更新和批量删除操作。
- `exports`：基于当前筛选和显示列生成 Excel。

## 3. 个人视图与查询扩展

扩展 `GET /projects/{projectId}/work-items` 查询参数：

- `view=created-by-me|assigned-to-me|pending-for-me|watched-by-me|unclosed`
- `creatorId`、`priority`、`severity`、`module`、`tag`
- `dueFrom`、`dueTo`
- `sort=updatedAt,desc`
- `groupBy=status|owner|type|sprint`

`view` 由后端根据当前用户解析，客户端不能传入其他用户 ID 冒充个人视图。普通搜索继续使用 `keyword`，匹配 ID、标题、描述、模块和标签。

## 4. 保存筛选器

- `GET /projects/{projectId}/saved-filters`
- `POST /projects/{projectId}/saved-filters`
- `PUT /saved-filters/{filterId}`
- `DELETE /saved-filters/{filterId}`
- `PUT /saved-filters/{filterId}/default`

筛选条件使用结构化 JSON，不接收 SQL 或自定义表达式。服务端维护允许字段和运算符白名单。筛选器仅当前用户可见、可修改。

## 5. 列表偏好

- `GET /projects/{projectId}/view-preference`
- `PUT /projects/{projectId}/view-preference`

配置内容包括 `columns`、`sort` 和 `groupBy`。列名、排序字段和分组字段均需白名单校验。

## 6. 批量处理

- `POST /projects/{projectId}/work-items/bulk-update`
- `POST /projects/{projectId}/work-items/bulk-delete`

单次最多 200 条。批量更新支持状态、负责人、优先级、Sprint、模块和标签。后端逐项校验权限、资源归属和状态机，不使用全事务回滚；响应返回 `successes` 和 `failures`，失败项包含工作项 ID、错误码和原因。

批量删除仅项目管理员可调用。

## 7. 工作项关注

- `GET /work-items/{workItemId}/watchers`
- `POST /work-items/{workItemId}/watchers/me`
- `DELETE /work-items/{workItemId}/watchers/me`
- `GET /projects/{projectId}/watched-work-items`

项目成员和访客均可关注。工作项状态变化和新评论时向关注者创建站内通知；操作人本人不重复接收。

## 8. 通知中心增强

扩展 `GET /notifications`：支持 `read=true|false`、`type` 和 `workItemId` 筛选。保留已有单条已读和全部已读接口。

新增通知去重规则：同一工作项、同一接收人、同一通知类型在短时间窗口内合并更新，不重复插入多条。

## 9. Excel 导出

- `POST /projects/{projectId}/exports/work-items`
- `GET /exports/{exportId}`
- `GET /exports/{exportId}/download`

创建导出时传入结构化筛选条件、排序和显示列。导出记录保存创建人、项目、状态、文件路径、创建时间和过期时间。V1.1 数据规模较小，可同步生成并返回 `READY`；接口形态保留异步状态，便于后续扩展。

## 10. 数据模型

### saved_filters

`id, user_id, project_id, name, conditions_json, sort_json, group_by, columns_json, is_default, created_at, updated_at`

约束：`UNIQUE(user_id, project_id, name)`；同一用户和项目最多一个默认筛选器。

### user_view_preferences

`id, user_id, project_id, columns_json, sort_json, group_by, updated_at`

约束：`UNIQUE(user_id, project_id)`。

### work_item_watchers

`id, work_item_id, user_id, created_at`

约束：`UNIQUE(work_item_id, user_id)`。

### export_jobs

`id, project_id, creator_id, status, request_json, file_name, storage_path, expires_at, created_at`

## 11. 数据库迁移

- PostgreSQL 新增 `V4__v1_1_collaboration.sql`。
- H2 新增同版本 `db/migration/h2/V4__v1_1_collaboration.sql`。
- JSON 配置在 V1.1 使用文本列保存，由应用层进行 JSON 校验，避免 H2 与 PostgreSQL JSON 类型差异。
- 两套迁移保持相同表名、列名、索引和唯一约束。

## 12. 权限与错误处理

- 查询、筛选、保存个人配置、关注和导出：项目成员及访客。
- 批量更新：项目成员及项目管理员。
- 批量删除：仅项目管理员。
- 非项目成员访问项目资源统一返回 403。
- 资源不存在返回 404；结构化条件非法返回 400；状态流转冲突返回 409。

## 13. 不在 V1.1 API 范围

- 自定义字段、自定义问题类型和自定义角色。
- Excel 导入。
- 自动化规则和报表订阅。
- 用例库、测试执行和测试报告转缺陷。
- Webhook 配置与投递接口，仅在架构上预留事件能力。
