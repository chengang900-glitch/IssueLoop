# 企业统一认证与第三方协同 APP 登录设计（评审稿）

日期：2026-09-29；状态：认证功能仍为方案设计，未实施、未联调。

品牌调整已确认：中文“问题闭环管理系统”，英文“IssueLoop”；定位“面向项目协作的问题与需求闭环管理平台”；主张“让每个问题有结果，让每项需求有着落。”。效果稿已同步，以下现状描述中的旧名称为设计时记录。

## 1. 结论与边界

推荐：保留本地账号登录，新增标准 OIDC 企业统一认证登录，并增加可配置的“集成第三方协同 APP 登录”能力。管理员开启总开关后，可分别启用飞书、钉钉、企微；登录页只显示已启用的按钮。所有方式映射到同一个本地用户与项目权限。

本轮产出方案与独立登录页效果稿，不修改业务代码，不部署、不创建外部应用。默认按单企业部署、飞书/钉钉/企微企业应用设计；多租户 SaaS、通讯录同步、机器人通知、审批和全站移动端重构不在本次范围。

## 2. 已核实的项目现状

- 实际应用位于 rnd-workbench，Spring Boot 2.7.18 / Java 11，原生 HTML/CSS/JavaScript。
- AuthService 校验本地账号与 BCrypt 密码，签发自有 JWT；前端用 sessionStorage 保存令牌。
- JwtAuthFilter 每次请求复核用户状态、角色及 tokenVersion，已有首次改密约束。
- User 没有外部身份表，也没有邮箱/手机专用字段；passwordHash 当前不能为空。不能把 username 视为已验证邮箱。
- 登录页由 script.js 的 installLoginView 动态创建，采用浅绿双栏布局；仓库根目录另有静态文件，本次实施应以 rnd-workbench 的资源为准。

上述均为当前源码证据，未验证运行中的生产部署。

## 3. 方案选择

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| A：Keycloak OIDC + 协同 APP 直连 | 各平台按官方能力接入；可独立开关；保留现有权限 | 维护三个平台适配器 | 推荐 |
| B：协同 APP 统一经 Keycloak 代理 | 企业认证集中管理 | 依赖 Keycloak 身份代理能力，平台内免登多一层转换 | 已有成熟身份代理时采用 |
| C：全量改成 Keycloak 账号与会话 | 认证体系统一 | 用户迁移、权限与 JWT 链路改造范围大 | 不作为本轮方案 |

## 4. 三条登录路径

### 4.1 企业统一认证登录

登录页“企业统一认证登录” → 服务端创建短期认证事务 → Keycloak 授权页 → 后端回调换取并校验身份 → 查找本地绑定 → 校验账号状态 → 签发项目会话 → 返回原目标页面（无目标时进入工作台）。

使用 OIDC Authorization Code + PKCE S256，优先采用 Spring Security OAuth2 Client 标准能力，不使用密码直传模式。验证 state、nonce、签名、issuer、audience、有效期。企业密码、MFA 均由 Keycloak 页面处理。本项目不提供企业密码输入框。

已有有效 Keycloak 登录会话且策略允许时可免输密码；首次登录、会话失效或企业 MFA 策略仍可能要求交互。企业入口不应一打开普通登录页就强制跳转，避免循环和阻断备用登录。

### 4.2 第三方协同 APP 登录总开关与平台选项

后台管理增加参数卡片“集成第三方协同 APP 登录”：

- 总开关“启用集成第三方协同 APP 登录”，默认关闭。
- 关闭时隐藏下方平台选项，登录页不显示任何协同 APP 登录按钮。
- 开启时展开三个独立复选项：飞书、钉钉、企微；只有勾选的平台才显示对应登录按钮。
- 保存时校验：总开关开启必须至少选择一个平台；关闭总开关时保留上次勾选值但不生效，便于恢复配置。
- 每个平台还需有独立的“配置完成/启用”状态；未完成 App ID、密钥、回调地址和企业范围校验时，不能显示为可用登录入口，管理员页面显示缺失项。
- 建议按钮显示为“飞书登录”“钉钉登录”“企微登录”，不把“第三方协同 APP”作为用户需要理解的技术术语。
- 前端只读取服务端返回的可用提供方列表，不能自行根据环境变量决定显示。

推荐配置数据结构：`thirdPartyAppLoginEnabled`、`feishuEnabled`、`dingtalkEnabled`、`wecomEnabled`，以及各平台的 issuer/appId/回调配置（密钥只存服务端密钥管理，不返回前端）。审计记录总开关及平台开关的变更人、时间和变更前后值。

### 4.3 浏览器飞书登录

“飞书登录” → 飞书官方授权页面 → 用户扫码或确认授权 → 后端通过授权码获取用户身份 → 企业范围校验 → 本地绑定 → 项目会话。

首版推荐跳转飞书官方授权页，不在项目页自行绘制二维码。扫码方式由飞书官方页面和设备环境决定。取消授权返回登录页并显示可重试提示。

### 4.4 钉钉登录

“钉钉登录”进入钉钉官方授权/扫码流程；后端使用一次性授权码换取身份，校验企业范围、应用可用人员范围和本地绑定后签发项目会话。钉钉工作台入口使用同一身份绑定，但具体免登 API、回调参数和客户端差异必须按实施时官方文档锁定，不复用飞书协议字段。

### 4.5 企微登录

“企微登录”进入企业微信网页授权流程；后端通过授权码获取企业微信用户标识，校验 corp/app 范围及本地绑定后签发项目会话。企微侧应用入口与网页登录共用绑定记录，但不把 `open_id`、`userid` 等不同平台标识混用。

### 4.6 飞书工作台应用入口

在飞书开放平台创建企业自建应用，启用网页应用，配置桌面端/移动端主页、回调 URL、所需安全域名、最小用户身份权限及应用可用人员范围，发布并经企业管理员审核。

主页指向项目专用入口 /auth/feishu/entry：

1. 飞书工作台打开应用；先检查本项目会话，有效则进入目标页面。
2. 无有效会话时调用飞书支持的网页免登/授权能力，获取临时 code；后端换取用户身份。
3. 通过企业范围、身份绑定、本地启用状态检查后进入工作台。
4. 首次授权可能弹出同意页面；失败、超时、不支持客户端时显示重试和其他登录方式，不反复自动跳转。

User-Agent 只用于界面引导，不能作为可信身份。不能只把项目 URL 放进飞书就宣称已经免登。JS SDK 方法及令牌接口需在实施时按当前官方文档和目标客户端版本锁定，禁止混搭旧版示例。

## 5. 账号与权限：先关联，后放行

- 增加 user_external_identity：user_id、provider、provider_instance、subject、tenant_key、created_at、last_login_at。
- OIDC 身份键为可信配置的 issuer + sub；协同 APP 身份键按 `provider + app_id/corp_id + tenant_scope + provider_user_id` 保存。数据库建立对应唯一约束，保证并发首次关联不会串号。
- 同一本地用户可绑定多个不同平台身份，但同一平台同一企业范围内一个外部身份只能绑定一个本地用户；原 user_id、任务归属、项目成员及权限不变。
- 不根据姓名、邮箱、手机号自动合并；飞书传来的姓名只作展示信息。
- 首版默认不自动注册：已绑定直接登录；未绑定显示“身份验证成功，请关联工作台账号”。用户通过原账号密码重新验证后绑定；无原账号则联系管理员开通。关联需绑定本次已验证外部身份的短期、单次票据，并应用本地登录限流和锁定规则。
- 管理员可预先绑定经核实的外部标识；冲突时禁止覆盖并记录审计。解绑要重新验证身份，并防止删除用户最后一种可用登录方式。
- 新增 local_login_enabled；只有外部认证的用户禁用本地密码入口，可保留随机不可用密码散列以兼容现有非空字段，不向用户分发默认密码。
- 外部身份不直接授予系统管理员或项目权限；角色仍由本项目管理。
- 必须调整首次改密约束：本地密码登录继续强制改密；可信外部认证会话不要求修改本地密码，也不能把原本的 mustChangePassword 清除。JWT 需携带服务端签发的认证方式，相关前后端逻辑共同适配。
- 本地密码失败锁定只限制密码认证及密码关联；本地账号停用阻止全部方式。

## 6. 会话与安全设计

保留现有业务 JWT，外部令牌只在服务端使用，不发送到浏览器、URL、日志或业务接口。登录事务使用服务端存储，包含 state、nonce、PKCE verifier、目标路径、过期时间、流程类型；绑定 Secure / HttpOnly / SameSite=Lax 的短期 Cookie。一次消费后删除，限制尝试次数，多实例使用共享存储，不引入对单机内存的生产依赖。

回调完成后以短期 HttpOnly 交接 Cookie 重定向到固定的 /auth/complete 页面；前端通过同源 POST 兑换项目 JWT。兑换原子消费，校验 Origin 和事务绑定，响应 no-store；响应体交给现有登录初始化流程。URL 中不携带项目 JWT。回调页不载入第三方资源并设置 Referrer-Policy。

仅允许配置好的认证源与回调地址，登录后目标只允许站内相对路径。生产 HTTPS；密钥从环境或密钥管理注入，不放仓库。新增 Cookie 相关流程需专门的 CSRF / Origin 校验，并将当前凭据型 CORS 收紧到明确来源。业务 API 保留 Bearer 模式，不盲目切换全站 Cookie 认证。

JWT 继续检查本地 status、tokenVersion。新增可撤销认证会话记录（sid、user_id、provider、外部 sid、过期/撤销时间），新签发令牌携带 sid，过滤器验证会话有效性；迁移时明确旧令牌过渡或统一失效策略。

默认“退出登录”只撤销当前项目会话并清理前端令牌；飞书入口本次退出后不自动再次免登，显示手动继续登录。企业会话提供明确的“退出企业统一登录”操作，采用 Keycloak RP-Initiated Logout；配置 Back-Channel Logout 时验证注销令牌并撤销关联的本地会话。不擅自退出整个飞书客户端。

必须说明边界：上游停用账号不自动等于本项目既有 JWT 立即失效。Keycloak 管理策略需联动会话注销并联调验证；未配置事件联动的飞书账号变更，首版以短会话及重新认证收敛，建议外部会话最长 1 小时且不静默续期。要求离职即时禁用时，必须同步停用本地账号或增加经授权的事件集成，不作为已实现能力宣传。

## 7. 页面设计

效果稿：../../designs/2026-09-29-login-sso-feishu.html（独立演示，不调用真实登录接口）。

沿用浅绿、暖白、双栏、R 标识和协作叙事。右栏顺序为标题 → 企业统一认证登录（绿色主按钮）→ 已启用的飞书/钉钉/企微按钮 → “或使用账号密码” → 账号/密码 → 账号登录（次级按钮）。不在普通用户按钮中暴露 OIDC、issuer 等术语。

总开关关闭时不显示任何协同 APP 按钮；开启后按三个子开关动态显示。运行时故障只影响对应平台，显示明确提示并保留其他入口。所有错误用行内可访问状态呈现，不显示原始令牌、第三方返回详情。

飞书内从专用入口进入，优先展示“正在通过飞书登录”，失败后提供“重试”和“其他登录方式”；未绑定进入关联页，账号停用则提示联系管理员。移动端登录页单栏适配；现有业务页面是否适合飞书移动端需单独验收，不能因登录页适配就宣称全站适配。

效果稿可切换普通登录、飞书内认证、首次关联和失败状态；顶部切换条属于设计评审工具，不属于正式产品。

## 8. 实施范围与依赖

建议分四步：身份绑定与会话基础 → Keycloak → 飞书浏览器与客户端 → 页面及部署联调。

涉及 User/身份实体、H2/PostgreSQL 双迁移、AuthService/Controller、JwtAuthFilter、SecurityConfig、JWT/会话管理、配置、前端登录与个人账号/用户管理的必要部分。新增 OAuth2 Client 依赖，沿用当前项目结构，不同时升级整个技术栈。

配置首版由部署环境提供，不新增完整“认证中心”管理后台。前端只读取可公开的提供方启用状态及显示名称。

实施前需要：实际 HTTPS 域名与反向代理路径；Keycloak issuer、Client ID、密钥及回调/注销配置；飞书 App ID、App Secret、企业范围、应用管理权限；各准备一个已关联、未关联、停用账号用于联调。密钥通过安全渠道配置，不写入设计文档。

当前默认决策：单企业自建应用、不自动注册、保留本地备用登录。若需企业严格禁止密码绕过 MFA，可按用户关闭 local_login_enabled，并保留受控应急管理员；飞书直连是否满足企业 MFA 政策亦需纳入接入确认。

## 9. 验收标准

1. 同一用户以三种方式登录，user_id、项目列表、角色、任务归属一致。
2. Keycloak 首次登录、已有 SSO 会话、MFA、取消授权、服务故障均按设计处理。
3. 飞书外浏览器授权，以及飞书桌面端/移动端工作台入口分别完成真实登录；记录测试客户端版本。
4. 未绑定用户必须关联或由管理员开通；异企业、冲突绑定、停用用户无法登录，且不能通过更换入口绕过。
5. state/nonce 错误、code 重放、交接票据重放、开放重定向、过期会话、伪造用户信息均被拒绝。
6. 本地首次改密仍有效，外部认证不误弹本地改密；密码重置、账号停用继续撤销旧令牌。
7. 普通退出不会立刻自动登录回来；企业联合退出/后台注销经真实 Keycloak 验证；飞书退出只影响本项目。
8. 桌面及窄屏登录入口完整、键盘可达，网络失败可恢复；全站移动业务体验单独记录。
9. 密钥与外部令牌不出现在静态文件、浏览器存储、URL 或日志；不把提供方 token 当本项目 token。
