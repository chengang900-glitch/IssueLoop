# 用户管理与首次项目引导设计

## 目标

让空数据库首次部署后，系统管理员可以创建首个项目并管理用户；普通用户可以维护本人的部门和密码。用户岗位信息与系统权限、项目权限保持分离。

## 已确认规则

- 系统权限仅有 `ADMIN` 与 `USER`；仅 `ADMIN` 可以访问用户管理。
- 岗位字段只用于组织信息，允许值为：项目经理、实施顾问、开发顾问、测试顾问。
- 项目权限继续使用 `PROJECT_ADMIN`、`MEMBER`、`GUEST`，不从岗位自动推导。
- 新增用户和管理员重置密码均设为 `123456`，并要求下次登录修改密码。
- 用户可以修改自己的部门；修改密码必须提供原密码。
- 本次只做本地验证，不执行 JAR 打包。

## 数据模型与迁移

在 `users` 表增加三个字段：

- `department VARCHAR(64)`：部门，可空。
- `job_role VARCHAR(32)`：岗位，可空，仅允许四个已确认岗位。
- `must_change_password BOOLEAN NOT NULL DEFAULT false`：控制首次登录修改密码。

为 H2 与 PostgreSQL 分别增加 V5 迁移，字段语义和默认值保持一致。既有用户默认无需修改密码；新建和重置的用户标记为需要修改。

## 后端接口与权限

### 管理员用户管理

- `GET /api/v1/users`：分页查询用户，返回用户名、姓名、部门、岗位、系统权限、状态。
- `POST /api/v1/users`：创建用户；用户名为邮箱格式，密码后端固定加密为 `123456`，系统权限默认 `USER`，并设置 `mustChangePassword=true`。
- `PUT /api/v1/users/{id}`：更新姓名、部门、岗位、系统权限、状态；岗位和系统权限均做白名单校验。
- `PUT /api/v1/users/{id}/status`：启用或禁用账号。
- `POST /api/v1/users/{id}/reset-password`：将密码重置为 `123456`，清空锁定状态并要求下次登录修改。

所有接口在服务端校验当前用户为 `ADMIN`，前端隐藏不是安全边界。

### 本人账户

- `GET /api/v1/auth/me` 增加部门、岗位和 `mustChangePassword`。
- `PUT /api/v1/users/me` 支持更新部门与密码；更改密码时必须验证原密码，成功后清除 `mustChangePassword`。
- 登录后若 `mustChangePassword=true`，显示不可关闭的密码修改弹窗；完成修改前不加载业务工作台。

## 前端交互

### 首次项目

- 没有项目时，工作区显示“创建第一个项目”主按钮。
- 系统管理员点击后打开项目表单，填写项目名称、简称、描述；创建者自动成为项目管理员。
- 普通用户没有项目时看到“等待加入项目”的说明。
- 左侧依赖当前项目的菜单在没有项目时不调用 `/projects/null/...`，而是显示明确提示。

### 用户管理

- 管理员左侧新增“用户管理”入口。
- 页面以表格展示用户，提供新增与编辑弹窗，并有启用/禁用、重置密码操作。
- 岗位下拉仅展示四种已确认岗位；系统权限下拉仅展示系统管理员、普通用户。
- 新建与重置成功后，以提示明确显示初始密码为 `123456`。

### 本人账户

- 左下角账户区域可点击。
- 弹窗展示用户名、姓名、岗位；部门可编辑。
- 密码修改区包含原密码、新密码、确认新密码；两次新密码必须一致。

## 错误处理

- 用户名重复、非邮箱用户名、非法岗位、非法系统权限均返回明确的参数错误。
- 禁用用户不能登录；重置密码解除之前的失败锁定。
- 未选项目的导航、导出、创建工作项、筛选等操作显示“请先选择或创建项目”，不发出无效请求。
- 普通用户尝试访问管理员接口返回无权限。

## 验收与验证

- 后端单元测试覆盖：新用户初始密码标记、管理员重置密码、岗位白名单、本人修改密码清除标记、普通用户访问用户管理被拒绝。
- 前端检查：`node --check src/main/resources/static/script.js`。
- 本地浏览器验证：管理员首次登录创建项目；左侧导航切换；管理员新增用户、禁用/启用、重置密码；用户账户修改部门与密码。
- 构建验证仅执行 `mvn test`，不执行 `package`。
