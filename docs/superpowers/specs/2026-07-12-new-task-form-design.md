# 新建任务表单优化设计

日期：2026-07-12  
状态：已确认，待实施

## 1. 目标与范围

参考企业问题管理工具的完整录入体验，优化本系统的“新建任务”页面。页面应先帮助用户定义任务，再记录任务属性，避免现有表单把描述和基础属性混排。

本次范围包括：任务标题、所属项目、任务类型、富文本描述、附件、优先级、严重程度、负责人、关注人、主模块、子模块、所属迭代、截止日期、标签、预计工时和关联任务。

本次明确不包括发布里程碑和受影响里程碑。

任务状态统一为“新建、进行中、延期处理、已完成、已验收、验收不通过、已拒绝”。“重新开始”是任务负责人从“验收不通过”或“已拒绝”回到“进行中”的操作记录，不作为长期停留状态。

## 2. 页面布局

新建任务采用单页分层表单，不采用折叠属性或左右双栏布局。填写顺序固定为：

1. 可展开的“任务流程说明”。
2. 任务标题、所属项目、任务类型。
3. 任务描述。
4. 附件。
5. 全部任务属性。
6. 取消与创建任务操作。

页面结构如下：

```text
新建任务
任务流程说明（点击展开）
任务标题 *
所属项目 *
任务类型 *

任务描述 *（富文本）

附件

任务属性
优先级        严重程度
负责人        关注人
主模块        子模块
所属迭代      截止日期
标签          预计工时
关联任务

取消          创建任务
```

任务标题、所属项目、任务类型和描述是必填项。所有任务属性必须位于描述框之后，不得与顶部核心信息混排。

## 3. 顶部核心信息

- **任务标题**：单行输入，必填。
- **所属项目**：必选。若从具体项目上下文进入，默认带入当前项目；仍可切换至当前用户有创建权限的项目。若从全局入口进入，必须主动选择。
- **任务类型**：必选，沿用现有分类：需求、任务、测试、缺陷；不新增或改变分类。

创建任务后的初始状态固定为“新建”，并自动记录创建人和创建时间。

### 3.1 任务流程说明

新建任务标题下方提供一个默认收起的“任务流程说明”入口。展开后展示状态流转图、各状态含义与操作权限；关闭后不影响已填写内容。

流转规则如下：

- 新建 → 进行中：负责人、创建人或项目管理员开始处理。
- 新建 / 进行中 → 已拒绝：创建人或项目管理员拒绝任务，必须填写原因。
- 进行中 → 延期处理：负责人、创建人或项目管理员申请延期，必须填写申请原因和新的截止日期。
- 延期处理 → 进行中：项目管理员、创建人或负责人审批通过并更新截止日期；审批驳回时同样回到进行中，维持原截止日期并记录驳回原因。
- 进行中 → 已完成：负责人、创建人或项目管理员提交完成。
- 已完成 → 已验收 / 验收不通过：负责人、创建人或项目管理员验收；验收不通过必须填写原因。
- 验收不通过 / 已拒绝 → 进行中：仅负责人可执行“重新开始”，必须填写重新开始说明。
- 已验收为终态。

## 4. 富文本描述与附件

### 4.1 描述

描述采用富文本编辑器，并保留常用的标题、加粗、斜体、列表、链接、引用、代码、表格和图片能力。描述是必填项，应提供足够高度，成为页面的主要录入区域。

用户粘贴截图时，系统应：

1. 在描述原位置直接显示图片预览。
2. 将图片作为任务附件统一保存和管理。
3. 在创建或编辑后保持描述中的图片位置。

### 4.2 附件

描述框下方保留独立附件区，支持拖拽文件、选择文件、批量上传和删除待上传附件。独立上传的文件在附件列表展示名称、类型、大小和删除操作；描述内粘贴的图片亦在该列表中可识别和管理。

## 5. 任务属性

| 属性 | 交互与规则 |
|---|---|
| 优先级 | 单选，沿用 P0、P1、P2、P3，默认 P2。 |
| 严重程度 | 单选，沿用致命、严重、普通、轻微，默认普通。 |
| 负责人 | 从项目成员中单选；可为空，表示未分配。 |
| 关注人 | 从项目成员中多选；创建后接收该任务的相关动态通知。 |
| 主模块 | 从当前项目模块中选择；可为空。 |
| 子模块 | 依赖主模块选择；未选主模块时不可选。 |
| 所属迭代 | 从当前项目迭代中选择；可为空。 |
| 截止日期 | 日期选择；可为空，到期与逾期按现有提醒和列表规则展示。 |
| 标签 | 支持多选已有标签或创建标签。 |
| 预计工时 | 数值输入，单位为小时，允许 0.5 小时递增；可为空。 |
| 关联任务 | 支持搜索、多选当前项目内任务；创建后在新任务与被关联任务的详情页均显示关系。 |

“主模块”和“子模块”替代现有单一模块选择的展示方式；数据层可继续以模块层级关系存储，避免将子模块作为无上下文的独立值。

## 6. 数据、权限与通知

- 新建任务时除既有字段外，需持久化关注人、预计工时和关联任务。
- 关注人仅可选择当前项目成员；非成员不允许保存。
- 关联任务仅可选择同一项目中用户有访问权限的任务；任务不得关联自身，重复关联需去重。
- 创建人、负责人和关注人按既有权限和通知规则处理；任务创建人不因自身创建动作收到重复通知。
- 预计工时为非负小数，统一以小时保存与展示。

## 7. 交互与校验

- 标题、项目、类型、描述为空时，禁止提交并在字段旁展示明确提示。
- 项目切换后，负责人、关注人、模块、迭代和关联任务候选项必须刷新；已经不属于新项目的已选值必须清空并提示用户重新选择。
- 创建提交期间禁用重复提交；成功后关闭表单、打开新任务详情并显示创建成功提示。
- 上传失败、富文本图片处理失败或关联任务校验失败时，保留用户已填写内容，并显示可理解的失败原因。

## 8. 验收标准

1. 标题、所属项目、任务类型固定在描述框前，其他属性全部在描述框后。
2. 描述可编辑富文本，可直接粘贴图片并在正文位置预览。
3. 附件区仍可独立上传、批量管理文件。
4. 关注人、预计工时、关联任务可创建、持久化并在任务详情中查看。
5. 关联任务限制为同项目，不能关联自身或重复关联。
6. 不出现发布里程碑、受影响里程碑字段或相关数据处理。
