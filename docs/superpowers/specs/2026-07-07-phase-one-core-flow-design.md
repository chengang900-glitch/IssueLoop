# 研发工作台第一阶段核心闭环设计

日期：2026-07-07  
状态：待实施

## 1. 目标

在不迁移前端框架、不扩展 V2 功能的前提下，将现有原生 HTML/CSS/JavaScript 前端与 Spring Boot 后端接通，形成可验证的最小使用闭环：

登录 → 选择项目 → 查看工作项 → 创建工作项 → 查看详情 → 执行合法状态流转。

同时修复会破坏权限边界、数据一致性或附件安全的明确问题，并为核心行为补充自动化测试。

## 2. 范围

### 2.1 后端修复

- 项目访客仅允许查询，不允许创建、编辑、流转、评论或上传附件。
- 模块删除、Sprint 更新和 Sprint 删除必须校验对应项目的项目管理员权限。
- 附件下载必须先通过工作项所属项目的成员权限校验。
- 附件上传限制为单文件不超过 50MB，并采用明确的 MIME 白名单。
- 附件存储目录统一使用 `app.storage.path`，不在控制器中写死路径。
- “分配给我”仅在负责人为空时允许，并按状态机进入“已分配”。
- 工作项编号生成改为数据库并发安全方案，避免“查询最大值再加一”产生重复编号。

### 2.2 前端联调

- 保留现有原生 HTML/CSS/JavaScript，不引入 React、Vue 或构建工具。
- 增加账号密码登录界面。
- JWT 保存于 `sessionStorage`，关闭标签页后失效；请求统一携带 `Authorization: Bearer <token>`。
- 401 响应统一清理登录态并返回登录界面。
- 项目列表、项目汇总、工作项列表、工作项详情、创建工作项和状态流转改用真实 API。
- 当前登录用户从 `/api/v1/auth/me` 获取，不再写死“张伟”。
- 首次登录若没有可访问项目，显示明确空状态，不注入演示数据。
- 不在本阶段重做现有视觉样式；只增加完成登录和错误反馈所需的最小界面。

### 2.3 自动化测试

- 登录成功、密码错误及连续失败锁定。
- 项目管理员、成员、访客的读写权限边界。
- 模块和 Sprint 管理接口的越权防护。
- 附件下载和上传的项目权限、大小及类型校验。
- 工作项创建、查询、编辑和删除。
- 合法与非法状态流转。
- “分配给我”的前置条件。
- 并发创建工作项时编号不重复。

## 3. 不在本阶段实施

- React/Vue 迁移或前端工程化重构。
- 企业微信 SSO 或消息推送。
- Excel 导出与批量导入。
- Docker 部署。
- 图片缩略图。
- 完整子任务交互。
- 看板拖拽、燃尽图、容量规划等 V2 功能。

## 4. 架构与数据流

前端继续由 Spring Boot 静态资源目录提供。浏览器通过统一 API 请求函数访问 `/api/v1`：请求函数负责 JSON 编解码、JWT 请求头、统一响应结构解析及错误展示。

后端控制器负责参数接收和资源定位；项目权限由 `ProjectService` 集中校验；业务规则由对应 Service 执行；JPA Repository 负责持久化。新增 `work_item_counters` 计数表，以 `type` 为主键，通过 PostgreSQL `INSERT ... ON CONFLICT ... DO UPDATE ... RETURNING` 原子取得全局下一序号；编号生成与工作项保存处于同一事务。采用按类型全局自增，是因为工作项 ID 当前是数据库全局主键，按项目重复编号会产生主键冲突。

## 5. 权限规则

- 系统管理员：创建项目、管理系统用户。
- 项目管理员：项目内全部读写操作及成员、模块、Sprint、工作项删除。
- 项目成员：读取项目，创建/编辑/流转工作项，评论和上传附件。
- 项目访客：仅查询项目内容和下载已有附件。
- 非项目成员：不得访问项目及其工作项、评论、活动或附件。

所有通过工作项、附件、模块或 Sprint ID 访问的接口，必须先解析其所属项目，再执行项目权限校验。

## 6. 错误处理

- 后端继续使用统一 `ApiResponse` 和现有错误码。
- 参数错误返回 400；未登录返回 401；权限不足返回 403；资源不存在返回 404；非法状态或并发冲突返回 409。
- 前端对 401 执行登出；对其他错误显示后端 message，不静默失败。
- 创建或更新失败时保留用户已填写的数据，允许修改后重试。

## 7. 验收标准

1. 使用初始化管理员账号可以登录并获取 JWT。
2. 管理员可以创建项目，项目成员可以完成工作项核心流程。
3. 访客执行任何写操作均得到 403。
4. 非项目成员无法访问工作项和附件。
5. 两个并发创建请求不会生成相同工作项 ID。
6. 非白名单或超过 50MB 的附件被拒绝。
7. 前端核心页面不再依赖内存模拟项目和工作项数据。
8. 核心自动化测试通过，Maven 构建成功。
9. 使用 PostgreSQL 空库启动后，Flyway 能完成迁移并跑通登录至状态流转流程。

## 8. 实施顺序

1. 先补测试基础和可复现的失败用例。
2. 修复项目权限、附件安全和工作项编号。
3. 实现前端 API 客户端和登录态。
4. 依次接通项目、汇总、工作项列表、详情、创建和状态流转。
5. 运行自动化测试、Maven 构建及 PostgreSQL 核心流程验收。
