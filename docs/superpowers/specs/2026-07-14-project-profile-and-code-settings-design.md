# 项目档案与项目编号设置设计

日期：2026-07-14  
状态：已确认，待实施

## 1. 目标与范围

将当前仅含名称、简称和说明的项目记录扩展为面向“项目实施任务、开发任务”的项目档案；新增管理员专属“系统设置”菜单，用于维护新建项目的编号前缀。范围不包含合同、预算、回款或采购管理。

## 2. 项目编号规则

- 仅系统管理员可以在“系统设置”中查看和修改项目编号前缀。
- 前缀为 1 至 16 位的大写字母、数字或连字符；默认值为 `PRJ`。
- 新项目编号由服务端生成：`{前缀}-{YYYYMM}-{三位流水号}`，例如 `PRJ-202607-001`。
- 每月流水号按当前前缀独立递增，从 `001` 开始；以数据库唯一约束保证并发下不重复。
- 修改前缀仅影响之后创建的项目；历史项目编号不可重新生成或编辑。

## 3. 项目档案字段

### 3.1 基础身份

| 字段 | 规则 |
|---|---|
| 项目编号 | 系统生成、全局唯一、只读。 |
| 项目名称 | 必填，沿用现有长度限制。 |
| 项目简称 | 必填，沿用现有长度限制。 |
| 项目类型 | 必填：实施、开发、升级、运维；默认“实施”。 |
| 所属业务线 | 可选文本。 |
| 客户名称 | 可选文本。 |
| 交付地点 | 可选文本。 |
| 项目说明 / 目标 | 复用现有 `description`。 |

### 3.2 组织与计划

| 字段 | 规则 |
|---|---|
| 项目经理、实施负责人、开发负责人 | 可选用户引用；候选人为启用用户。 |
| 客户方负责人 | 可选文本。 |
| 计划开始 / 结束日期、实际开始 / 结束日期 | 可选日期；结束日期不得早于对应开始日期。 |
| 当前阶段 | 必填：立项、实施、开发、测试、上线、验收、运维；默认“立项”。 |
| 项目状态 | 必填：未启动、进行中、已暂停、已完成、已关闭；默认“未启动”。 |
| 健康状态 | 必填：正常、关注、风险；默认“正常”。 |

### 3.3 交付与管理

| 字段 | 规则 |
|---|---|
| 项目范围 / 主要模块、关键交付物、验收标准 | 可选多行文本。 |
| 风险说明、当前问题、下阶段重点工作 | 可选多行文本。 |
| 实施方式 | 必填：驻场、远程、混合；默认“混合”。 |
| 上线日期、运维支持截止日期 | 可选日期。 |

项目成员继续复用现有项目成员管理，不在项目档案中复制维护。

## 4. 里程碑清单

每个项目可维护多条里程碑记录，每条包含：里程碑名称（必填）、计划日期（必填）、实际完成日期（可选）、状态（未开始、进行中、已完成、已延期；默认未开始）与说明（可选）。

- 创建、编辑、删除里程碑要求项目管理员权限。
- 实际完成日期早于计划日期时自动标记为“已完成”；晚于计划日期时允许保留“已延期”。
- 里程碑按计划日期升序展示；删除不影响项目、任务或历史活动。

## 5. 权限与页面

- 系统管理员：可创建项目、维护系统设置、编辑任意项目档案；项目创建者仍自动成为项目管理员。
- 项目管理员：可编辑本项目档案、维护本项目里程碑和成员。
- 普通成员与访客：可查看所属项目档案和里程碑，不可编辑。
- “项目管理”列表新增项目编号、客户名称、项目经理、当前阶段、项目状态、健康状态等摘要列；点击项目进入项目档案详情页，可查看与编辑字段和里程碑。
- 新建项目弹框仅保留创建必填项：项目名称、简称、项目类型；项目编号自动显示为“创建后生成”。其他档案字段在创建后编辑，避免首建表单过长。

## 6. 数据与兼容性

- 使用 H2、PostgreSQL 对应的 Flyway V11 迁移，向 `projects` 增加档案列，新建 `project_milestones`、`system_settings` 与 `project_code_counters` 表。
- 历史项目按兼容默认值回填：编号为 `LEGACY-{项目ID}`，类型“实施”、阶段“立项”、状态“进行中”、健康“正常”、实施方式“混合”。
- API 的项目创建、更新、详情和列表 DTO 返回新字段；历史调用仍可只传名称、简称和说明。

## 7. 验收标准

1. 管理员可在系统设置保存编号前缀；非管理员不可见菜单且接口返回 403。
2. 新项目按当前前缀生成唯一的 `前缀-YYYYMM-三位流水号`，修改前缀不改变旧编号。
3. 项目档案可保存上述基础、组织、计划、交付和管理字段，并按权限控制编辑。
4. 每个项目可新增、编辑、删除多条里程碑并按计划日期展示。
5. 既有项目、项目成员、任务、迭代、模块和归档功能保持可用。
