# 高级筛选与保存筛选器设计

日期：2026-07-07  
状态：已确认，待实施

## 1. 目标

在现有工作项列表上完成“组合筛选—保存—再次应用—默认恢复”闭环。筛选器仅当前用户可见，不支持共享。

## 2. 实施范围

- 高级筛选字段：个人视图、类型、状态、负责人、创建人、优先级、严重程度、迭代、模块、标签、截止日期范围和关键词。
- 保存当前筛选条件和排序。
- 筛选器的查询、新建、重命名、设为默认和删除。
- 进入项目时自动应用当前用户在该项目下的默认筛选器。
- 本阶段不实现分组、显示列配置、筛选器共享和复杂自定义表达式。

## 3. 后端设计

使用已存在的 `saved_filters` 表，新增 `SavedFilter` 实体、Repository、Service 和 Controller。

接口保持现有 V1.1 契约：

- `GET /api/v1/projects/{projectId}/saved-filters`
- `POST /api/v1/projects/{projectId}/saved-filters`
- `PUT /api/v1/saved-filters/{filterId}`
- `DELETE /api/v1/saved-filters/{filterId}`
- `PUT /api/v1/saved-filters/{filterId}/default`

请求体使用结构化字段，由服务端序列化到 `conditions_json` 和 `sort_json`，不接收 SQL 或查询表达式字符串。

## 4. 校验与权限

- 个人视图只允许现有五个枚举值。
- 排序只允许 `createdAt`、`updatedAt`、`dueDate`、`priority` 和 `title`，方向只允许 `asc` 或 `desc`。
- 项目成员和访客均可使用个人筛选器；非项目成员返回 403。
- 只有筛选器所有者可修改、设为默认或删除。
- 同一用户和项目下名称不可重复。
- 设为默认时，在同一事务内取消该用户和项目下其他默认项。

## 5. 前端交互

- 工作项工具栏新增“高级筛选”和“保存筛选”按钮。
- 高级筛选使用弹窗编辑条件，点击“应用”后由后端执行查询，不再仅对当前 200 条数据做本地过滤。
- 保存时输入名称，完整保存个人视图、高级条件和排序。
- 侧栏展示已保存筛选器。点击后恢复其条件并重新查询。
- 默认筛选器显示明确标识。重命名、设为默认和删除放在筛选器的简化操作区。
- 删除当前已应用的筛选器后，保留当前查询条件，但清除“已保存”标识。

## 6. 数据流

1. 进入项目时先读取筛选器列表。
2. 若项目初次进入且存在默认筛选器，将其条件写入当前查询状态。
3. 前端将非空条件转换为已有工作项列表查询参数。
4. 后端合并个人视图与组合筛选条件，返回分页结果。

## 7. 错误处理

- 非法字段、枚举值、日期范围或排序返回 400。
- 非本人筛选器或非项目成员操作返回 403。
- 筛选器不存在返回 404。
- 同名冲突返回现有重复数据错误码。

## 8. 验收与测试

- 高级筛选条件正确转换为后端查询参数。
- 筛选器按用户和项目隔离。
- 重复名称被拒绝。
- 一个用户在一个项目下最多一个默认筛选器。
- 非法结构化条件和排序被拒绝。
- 应用、重命名、设为默认和删除后界面状态与后端一致。
- 前端 JavaScript 语法检查、后端全量测试和 Maven 打包全部通过。
