# V1.1 剩余能力综合设计

日期：2026-07-09  
状态：已确认，待实施

## 1. 范围与实施顺序

本次连续完成 V1.1 剩余能力，实施顺序固定为：

1. 批量删除。
2. 关注者通知、通知筛选和通知去重。
3. Excel 导出与下载。
4. 前端接入、全量测试和打包。

## 2. 批量删除

### 2.1 API

`POST /api/v1/projects/{projectId}/work-items/bulk-delete`

请求体包含 `ids` 和 `confirmation`。`ids` 为 1–200 个不重复的工作项 ID；`confirmation` 必须等于服务端约定的确认文字“确认删除”。

响应沿用批量更新的 `successes` 和 `failures` 结构。每个工作项独立事务删除，单项不存在或不属于项目时记录失败，不回滚其他成功项。

### 2.2 权限与前端

仅项目管理员可调用。前端批量操作区增加删除入口，用户需先确认弹窗，再输入“确认删除”。删除成功项从选择集移除，失败项保留选中。

## 3. 关注与通知增强

### 3.1 通知触发

- 工作项状态变化后，向所有关注者生成 `STATUS_CHANGED` 通知。
- 新增评论后，向所有关注者生成 `COMMENT_ADDED` 通知。
- 本次操作人不接收自己触发的通知。
- 批量状态修改与单条状态修改遵循相同通知规则。

### 3.2 五分钟去重

同一用户、工作项和通知类型在五分钟内只保留一条通知。再次触发时更新原通知内容并重置为未读。`STATUS_CHANGED` 和 `COMMENT_ADDED` 是不同类型，互不合并。

### 3.3 通知查询

`GET /api/v1/notifications` 新增可选参数：

- `read=true|false`
- `type=STATUS_CHANGED|COMMENT_ADDED|...`
- `workItemId=<id>`

参数之间使用 AND 语义。保留未读数、单条已读和全部已读接口。用户只能读取和修改本人通知。

### 3.4 前端

顶部通知入口显示真实未读数，打开通知列表后可按未读和类型筛选，可单条已读或全部已读。点击包含工作项 ID 的通知时打开工作项详情。

## 4. Excel 导出

### 4.1 API

- `POST /api/v1/projects/{projectId}/exports/work-items`
- `GET /api/v1/exports/{exportId}`
- `GET /api/v1/exports/{exportId}/download`

创建请求包含当前结构化筛选条件、排序和显示列顺序。后端复用工作项查询白名单与项目权限，最多导出 10,000 条。

导出同步执行，但保留任务状态模型：

- 成功：`READY`，记录文件名、路径和 24 小时后的过期时间。
- 失败：`FAILED`，保留任务记录供查询。

### 4.2 文件与安全

使用 Apache POI 生成 `.xlsx`。导出文件保存在应用可配置的本地导出目录，默认位于项目 `data/exports` 下。文件名不直接使用未清理的用户输入。

只有导出任务创建者可查询和下载。下载前同时校验 `READY`、未过期且文件仍存在。

### 4.3 导出列

固定列 ID 和标题始终导出，其余列按当前显示列和顺序输出。列白名单与视图偏好保持一致。日期使用明确的中国时区格式，不导出 HTML。

### 4.4 前端

现有导出按钮提交当前筛选、排序和显示列。任务返回 `READY` 后立即下载；失败时显示可理解错误。

## 5. 权限与错误

- 批量删除：仅项目管理员。
- 通知：只能访问当前用户数据。
- 导出：项目成员和访客均可创建，只有创建者可查询和下载。
- 非法结构化条件或显示列返回 400，越权返回 403，资源不存在返回 404。

## 6. 测试和交付标准

- 批量删除测试：管理员权限、确认文字、数量上限、项目归属和部分成功。
- 通知测试：关注者接收、操作人排除、五分钟去重、筛选组合和已读权限。
- 导出测试：查询条件、列顺序、数量上限、XLSX 内容、创建者权限和过期校验。
- 前端 JavaScript 语法检查通过。
- Maven 全量测试和打包通过。
- 只在上述验证全部通过后交付可测试 JAR。
