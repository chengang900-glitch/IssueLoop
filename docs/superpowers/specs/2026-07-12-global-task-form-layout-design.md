# 全局任务表单左右布局与任务详情排序设计

日期：2026-07-12  
状态：已确认，待实施

## 目标

统一任务相关表单的字段呈现：桌面端使用“标签在左、控件或内容在右”的左右布局；任务详情将描述固定为首个内容区；新建工作项中所属项目与任务类型同一行并列；任务流程说明由内嵌展开区改为标题区左上角入口和模态弹框。

## 范围与边界

- 只修改前端静态页面的结构、样式与交互；不改任务数据、接口、字段校验或状态流转规则。
- 桌面端表单项统一使用两列字段行，标签列保持一致宽度，控件列占用剩余宽度。
- 窄屏宽度下，两列字段行回退为上下布局，避免标签或控件挤压。
- 任务详情的描述区置于详情内容首位；其他字段紧随其后，保持既有内容和值不变。
- 新建工作项中：任务标题独占一行；所属项目和任务类型组成同一行的两列；任务描述位于其下，并在其后放置附件和任务属性。
- 流程说明入口显示在“新建工作项”标题左侧区域；点击后显示包含既有状态图、说明与权限文字的模态弹框；关闭不清空已填写表单内容。

## 实现方式

1. 在 `index.html` 为新建工作项重组核心字段和流程说明入口，复用既有模态遮罩结构，不增加后端依赖。
2. 在 `script.js` 增加流程说明弹框的开关事件，并调整详情字段的渲染顺序，使描述优先。
3. 在 `styles.css` 定义可复用的字段行、双列字段组、流程说明弹框及响应式回退规则，并仅针对任务相关表单和详情使用，避免影响登录及非任务页面。

## 验收标准

1. 桌面端任务表单字段标签位于左侧，控件或字段内容位于右侧；窄屏下自动恢复上下布局。
2. 新建工作项的任务标题在前，所属项目与任务类型同一行并列，任务描述随后显示。
3. 打开工作项详情时，任务描述在其他详情字段之前。
4. “任务流程说明”不再内嵌占据表单空间；从左上角入口打开弹框后，仍可查看原有状态流转和权限说明，关闭后保留表单输入。
5. 创建任务、关闭新建弹框及详情抽屉等已有操作保持可用。
