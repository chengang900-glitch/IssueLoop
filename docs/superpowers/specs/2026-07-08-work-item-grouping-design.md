# 工作项列表分组设计

日期：2026-07-08  
状态：已确认，待实施

## 1. 目标

完成工作项列表按状态、负责人、类型或迭代分组的能力，并将分组偏好按“用户 + 项目”持久化，从而完整收口 V1.1 的保存筛选器与列表配置阶段。

## 2. 分组字段

`groupBy` 只允许以下值：

- `status`：按工作项状态分组。
- `owner`：按负责人分组，空值显示为“未分配”。
- `type`：按需求、任务、测试和缺陷分组。
- `sprint`：按迭代 ID 分组，空值显示为“无迭代”。
- `null`：不分组。

## 3. 数据与接口

使用现有 `user_view_preferences.group_by` 字段及已有接口：

- `GET /api/v1/projects/{projectId}/view-preference`
- `PUT /api/v1/projects/{projectId}/view-preference`

`ViewPreferenceService` 对 `groupBy` 执行白名单校验。非法字段返回 400。无偏好数据时，默认 `groupBy=null`。

不新增分组查询接口，工作项列表仍返回普通分页数据。前端对当前已查询的结果进行分组展示。

## 4. 前端交互

- “视图设置”弹窗增加分组选择：不分组、状态、负责人、类型、迭代。
- 保存时将显示列、排序和分组一次写入视图偏好。
- 每个分组显示分组名、数量和展开/折叠按钮。
- 默认全部分组展开。
- 折叠状态只存在当前页面内存中；刷新、重新登录或切换项目后重置为全部展开。
- 应用已保存筛选器时不改变当前分组，避免与视图偏好冲突。

## 5. 渲染规则

- 未分组时保持当前列表渲染。
- 已分组时，先对前端现有筛选后的工作项进行分组，再在组内保留后端返回顺序。
- 分组标题占满表格宽度，工作项行仍使用当前动态列定义。
- 分组顺序按首次出现顺序保持，不另外重排，避免破坏当前排序语义。

## 6. 不在本次范围

- 服务端分组聚合和每组独立分页。
- 对分组进行拖拽排序。
- 按自定义字段或标签分组。
- 持久化分组折叠状态。
- 在保存筛选器中写入或应用 `groupBy`。

## 7. 验收与测试

- 后端接受四种合法分组字段及空值，拒绝其他值。
- 分组偏好可保存、覆盖并在项目重新进入时恢复。
- 未分配工作项和无迭代工作项分别进入独立分组。
- 分组标题显示正确数量，展开和折叠不改变数据。
- 无分组时不改变现有列表行。
- JavaScript 语法检查、后端全量测试和 Maven 打包全部通过。
